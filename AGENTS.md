# Agent instructions

This repository uses Codex. Keep project instructions here; do not generate
Claude or Cursor integrations.

## Working in this repository

- Use the [Beads skill](.agents/skills/beads/SKILL.md) for task tracking.
- Keep changes small and follow [DEVELOPMENT.md](DEVELOPMENT.md).
- Run `make test` for code changes (Swift tests and publishing checks).
  GUI checks use `make smoke-test` and require a logged-in desktop and
  Accessibility permission; report when they have not been run.
- Use non-interactive file operations (`cp -f`, `mv -f`, `rm -f`/`rm -rf`).
- Close completed Beads issues and report changed files, checks and remaining work.
- Do not commit, push, publish, rewrite Git history or run Dolt remote sync
  unless the user explicitly requests it. Local Beads database commits are
  separate from source-code Git commits.
- Do not rerun `bd init` for routine setup: it can create a Git commit and
  regenerate integrations for other editors. See [.beads/README.md](.beads/README.md).

## Beads Issue Tracker

Use Beads (`bd`) for durable task tracking in repositories that include it. Use the `beads` skill at `.agents/skills/beads/SKILL.md` (project install) or `~/.agents/skills/beads/SKILL.md` (global install) for Beads workflow guidance, then use the `bd` CLI for issue operations.

### Quick Reference

```bash
bd ready                # Find available work
bd show <id>            # View issue details
bd update <id> --claim  # Claim work
bd close <id>           # Complete work
bd prime                # Refresh Beads context
```

### Rules

- Use `bd` for all task tracking; do not create markdown TODO lists.
- Run `bd prime` when Beads context is missing or stale. Codex 0.129.0+ can load Beads context automatically through native hooks; use `/hooks` to inspect or toggle them.
- Keep persistent project memory in Beads via `bd remember`; do not create ad hoc memory files.

**Architecture in one line:** issues live in a local Dolt DB; sync uses `refs/dolt/data` on your git remote; `.beads/issues.jsonl` is a passive export. See https://github.com/gastownhall/beads/blob/main/docs/core-concepts/sync-concepts.md for details and anti-patterns.
